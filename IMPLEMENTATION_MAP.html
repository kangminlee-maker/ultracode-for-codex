Ultracode for Codex Implementation Map

Current state of the durable Codex workflow runtime, model capability boundary, and hybrid skill route.

Current goalReleased 0.7.1 (npm latest); parity roadmap complete. This release lands the request contract and failure-mode boundary for the built-in code-review — a request error hard-fails before any spend, the evidence gate keys on whether the reviewer can actually read the change, and a cited-ref grammar error is recoverable instead of discarding the run. Nothing is queued; the next work is net-new scope.
Runtime health216/216 unit + installed E2E green; lint gates npm test. Behavior-changing work is opt-in and default-off. Note the scope of that claim: default-off preserves the decisions (which paths are admissible, which runs fail), not the bytes of the agent prompt — the evidence context changed, so agent cache keys differ from 0.6.1 and a resume of a run started before 0.7.0 re-runs its agents.
Main riskTwo surfaces. Authority: web/MCP are egress channels, file-write runs unsandboxed with a path guard as sole containment, nested full-scope exec is gated only by the permission record. Judgment: --ref-policy lenient lets a review complete with findings dropped — guarded by an all-dropped hard fail, a degraded result block, and a launch-time stderr notice, because built-ins are not permission-gated and no prompt confirms the switch.
Recent decisionFailure-mode inversion (2026-07-27): hard-block only what is decidable before spend; degrade what is only knowable after it. Request errors reject at launch with rejected value + cause + remediation; a ref whose path is in evidence is normalized rather than fatal. Structural violations and lens decisions stay fatal at every policy.

Service Blueprint

Judgment question: how does a requested model/effort become a bounded, journaled workflow execution?

Current Architecture

AreaCurrent contract
Hybrid skillskills/ultracode-for-codex/SKILL.md positions native Codex Ultra for ad-hoc model-directed delegation and this package for durable workflows. The main Codex context owns decisions, edits, phase synthesis, progress projection, and critical re-checks; the CLI owns schema-enforced, journaled fan-out and resume anchors of jobId/runId/cwd.
CLI skillskills/ultracode-for-codex-cli/SKILL.md owns explicit CLI runtime operations: background jobs, attached runs, packaging, release checks, runtime-boundary validation, installed E2E, and local runtime artifacts.
CLIsrc/cli.ts exposes durable run, validate, resume, background control, skill sync, and setup surfaces. --validate is the zero-token pre-check: it validates the request contract and, for a change-evidence built-in, reports whether the gate would open, the allowed evidence refs, and every dropped path with its rule — through the same evidence builder and status collection the run uses. Before creating runtime truth, an attached child prepares the Codex backend: model/list resolves the effective model and validates the run-level effort. setup version 2 reports that same selected model and Ultracode-safe effort set. Progress remains stderr JSONL and the total result/failure channel remains stdout JSON.
Settingssettings.json owns workflow execution, progress, permission, retry, timeout, heartbeat, background paths, the default run-level effort, and the two review-policy defaults evidenceScope (default) and refPolicy (strict). The current default remains xhigh for compatibility; explicit medium, high, and catalog-supported max are first-class paths.
Runtimesrc/runtime/workflow-runtime.ts owns parsing, validation, scheduling, permission, retry, cancel, resume, and progress. An agent without explicit effort inherits the run-level effort. Built-in task is read-only analysis: its planner is medium and workers inherit the run tier. code-review level high is medium/high; the default deep profile is high/xhigh. max is accepted, while ultra is structurally rejected.
Request contractEach built-in declares the --args keys it reads (BUILTIN_REQUEST_CONTRACTS), validated in launch() before the permission gate, the journal, and any spend. Unknown or mistyped keys (with a suggestion), wrong types, unsupported level, and an unresolvable diffBaseRef are rejected through one formatter carrying rejected value, cause, remediation. The same validation runs on --validate and on resume — a resumed built-in is re-identified from the journal (workflowName + scriptHash) because resume classifies as script_path.
Change evidence and its gateThe gate asks whether the reviewer can actually see the change: a path counts only if it produced an included content block or a diff hunk, so a ref alone no longer opens it — and a file: ref is published under that same rule, so what may be cited and what may be reviewed cannot disagree. Withheld paths are disclosed as unavailable:file-evidence counts. Because that depends on file selection, the gate is decided after the prompt budget is filled, and evidence paths are selected first — hunkless ones (an untracked file has no patch) ahead of the rest. The runtime owns the rule and its diagnostic together: the built-in fails with the same string --validate reports — and --validate runs the same builder, not a re-derivation — naming how many paths git status found and which rule dropped each, or that paths were admitted but none was readable. Admission comes from one verdict function, so the predicate and the reported reason cannot drift. A resolvable diffBaseRef contributes file refs, so a committed range is reviewable on a clean tree. The prompt discloses #### Dropped From Evidence and a runtime-owned ref grammar; runtime-state paths are never named.
Journalsrc/runtime/workflow-journal.ts owns durable hash-chained workflow truth.
Model catalogsrc/codex/model-catalog.ts parses paginated app-server catalog responses, selects explicit/inherited/default models, exposes only runtime-safe efforts, and fails unsupported model/effort combinations before a turn.
Subagent backendsrc/codex/subagent-backend.ts has no hard-coded model fallback. It prepares the live catalog before the runtime journals an agent-capable run, strips provider credentials, serves bounded workspace tools, and caps Codex multi-agent V2 at one total thread so workers cannot create unjournaled descendants. Workers are read-only by default; the capability gates below add tools per run inside the same turn (accounting/journal intact). It provisions an isolated Codex home per run (web_search config, allowlisted [mcp_servers.*] slices, per-agent persona via thread/start.developerInstructions). On POSIX, shutdown terminates only the backend-owned process group; Windows terminates the direct child.
Orchestration primitivesagent(), parallel()/pipeline() (native-contract: stage gets (prev, item, index), 4096-item cap), and nested workflow(). A per-run concurrency pool bounds dispatch (--agent-concurrency); a per-run output-token ceiling self-paces (--budget). All spend is one hash-chained journal; resume replays the unchanged prefix.
Review-policy gates (opt-in, default-off)--evidence-scope all forgives only the evidence extension allowlist, making .java/.rb/.sql repositories reviewable; excluded directories, runtime state, and unsafe paths stay inadmissible at every scope, and prompt-budget file selection keeps its own allowlist. --ref-policy lenient drops the one candidate whose cited ref resolves to no path in evidence instead of failing the run, with an all-dropped hard fail, stats.refDrops, and a degraded block; a runtime drop carries its lifecycle subject (scope narrowing vs a rejected candidate vs a lost verifier result) plus a bounded projection of what was dropped; only candidate-lifecycle drops become synthesis decision rows, while stats.refDrops counts them all. Launch notices for a non-default policy ride the structured progress channel when stderr is the event stream, so a background progress.jsonl stays valid JSONL. The policy is baked into the built-in script text, so the two policies have different script hashes and a cross-policy resume is refused.
Capability gates (opt-in, default-off)Per-run flags that widen the worker's tool surface inside the Codex turn: --agent-web-search (native web_search), --agent-file-write (worktree-confined write_file/str_replace; the runtime path guard is the sole containment), --agent-mcp <s1,s2> (named-allowlist MCP servers sliced verbatim from ~/.codex/config.toml + auto-approved), and --agent-types (per-agent model + effort + persona from ~/.codex/agents/*.toml). Off (the default) is byte-identical; agentType is per-agent and enters the call key (resume auto-restores it).
Nested workflow()A child runs on the parent ctx (shared pool/budget/abort/journal chain); it emits only agent.*, keeping the journal single-run. Gated by --nested-workflows. Full-scope names (project/user/plugin) are permission-record-gated (mid-run can't prompt → fail-loud if unapproved). The value projector is per-execution, so children may run concurrently. One-level only; {scriptPath} deferred.
PackagePackage contents are the CLI runtime, install guide, both Codex skill command folders, docs, and public type exports. CLI --version and Codex clientInfo.version read package metadata, so packaging and npm version bumps update runtime surfaces together.

Current Decisions And Risks

Decision or riskCurrent state
Capability stream = worker authorityThe in-turn tool classes (web/file-write/MCP/agent-types) keep provider-reported turn accounting intact, so they were the safe subset to add; fan-out escapes (shell, multi-agent delegation) stay off. Each capability is opt-in, default-off, byte-identical when unused — that gate is the mitigation for the widened egress/exfil and unsandboxed-write surface. ultra effort stays structurally rejected (it would escape journal/cache/cost accounting), enforced even for agentType-supplied effort.
Nested-child authorityA mid-run nested workflow() cannot show a permission prompt, so a permission-required child (project/user/plugin) runs only against an existing allow record — else fail-loud. A child can never exceed the parent's approved isolation review (no silent widening). {scriptPath} nesting deferred for lack of a clean gate.
Realm marshaling under concurrencyConcurrent nested children each own a per-execution projector scope; the child return projects on success while errors propagate raw (double-projecting an error strips it to [object Object]). The hash chain is safe — the call-key critical section is synchronous, the same concurrency top-level parallel() already had.
Failure-mode boundaryHard-block only deterministically decidable violations; route the rest to non-blocking disclosure. Decidable before spend (request args, diffBaseRef resolvability, workspace-escaping paths, lens-decision refs) fails loud. Knowable only after spend (a cited ref's grammar) is normalized, then optionally degraded per candidate. The vacuous-pass guard is the safety property: drops with nothing verified fails, so a degraded review can never read as a clean one.
Claims retracted after review (2026-07-27)Three published claims were false and are corrected in place: “byte-identical when off” (the emitted context and agent cache keys change for every run), “absolute paths stay fatal at every policy” (drive-letter forms were degraded — now classified), and “a policy switch needs a fresh permission decision” (built-ins are not permission-gated; replaced by a launch-time stderr notice). Recorded because each was asserted in shipped docs before being tested.
Effort boundaryPackaged default is medium (lowered from xhigh after the 2026-07-14 review-quality A/B; quality saturates at medium, only latency scales). max stays single-agent; ultra cannot enter a workflow agent request.
Verification methodEvery capability/parity PR ran design-doc → GATE-0 real-path probe → adversarial design-verify (findings re-verified vs code) → default-off impl → falsifiability → dogfood/bot gate. The 2026-07-27 work added two independent review kinds on the same diff: a cross-family onto review (9 lenses, OpenAI/Codex gpt-5.6-sol, 24 findings collapsing to 4 distinct defects) and the Codex PR bot (9 distinct findings). They overlapped on 2 and diverged on the rest, so the union was acted on; every finding was re-derived against code before fixing. Residual: still no human review; the bot reviews only on open/ready/@codex review, never on push, so a merge gate has to request it explicitly.

Change Impact

SurfaceUser-visible effect
New run flags--agent-web-search, --agent-file-write, --agent-mcp <s1,s2>, --agent-types, --nested-workflows, --agent-concurrency, --budget, --evidence-scope, --ref-policy — all opt-in. A non-default --ref-policy prints a notice on stderr at launch, including when it comes from settings.json.
Built-in requestsBreaking, deliberately: a mistyped or unknown --args key, a non-string prompt, an unsupported level, or an unresolvable diffBaseRef now fails at launch instead of silently running the default. level accepts "xhigh" explicitly and is case-insensitive. run --validate --name code-review answers “would this run, and what could it cite?” for zero tokens.
Scriptsagent(prompt, {agentType}) resolves a named type; workflow(name|{script}) nests, now full-scope + concurrent; pipeline() stages receive (prev, item, index).
ResumeA resumed built-in is validated against its request contract, and a resume whose source ran under a different --ref-policy is refused (its cached results carry different failure semantics and the call keys do not record the policy). A direct --script-path launch of a persisted built-in is refused the same way: its policy is baked into the script text, so running it under another policy would execute one policy while reporting the other. Because the evidence context changed, a resume of a run started before this change re-runs its agents rather than reusing cache. A typed run auto-restores --agent-types from the journal (the type name is in the call key). An edited inline script resumes via a surfaced scriptPath + --resume-from-run-id, caching the unchanged prefix.
IsolationA completed isolation: "worktree" agent's worktree is reclaimed when it holds no real changes (git worktree remove decides); changed/stalled/aborted worktrees are preserved. workflow.worktreeRetention: preserve-all opts out.
Recoveryrecovery.retryable is derived from the failure reason (deterministic failures are not retried to --retry-limit); the effective catalog model is journaled, strengthening resume identity.
